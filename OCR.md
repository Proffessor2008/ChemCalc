# Распознавание химических формул с камеры/фото: анализ и план

## 1. Краткий вывод

Функция **реализуема** как отдельный модуль поверх текущего калькулятора и Telegram Mini App, но её нельзя делать «слепым» автозаполнением. Даже лучшие OCR-сервисы ошибаются на степенях окисления, зарядах, индексах и стрелках. Правильная схема:

1. Пользователь фотографирует или загружает изображение.
2. Клиент обрезает/выравнивает картинку.
3. Сервер распознаёт текст/LaTeX.
4. Формула нормализуется и проверяется текущим `parseEquation`/`balanceEquation`.
5. Пользователь видит **редактируемый** результат и нажимает «Вставить».
6. Только после этого формула попадает в калькулятор или стехиометрию.

Такой сценарий даёт пользу уже при точности 70–85%, потому что исправление одной-двух ошибок быстрее ручного ввода.

## 2. Что распознавать

- Молекулярные формулы: `H2SO4`, `Fe2(SO4)3`, `[Cu(NH3)4]SO4`.
- Уравнения: `Cu + 4HNO3 = Cu(NO3)2 + 2NO2 + 2H2O`.
- Ионные формы и заряды: `SO4^2-`, `Fe^3+`.
- Условия: `t`, `°C`, `H+`, `OH−`, катализаторы.
- Текстовые пояснения вокруг формулы.

Отдельно стоит распознавать **структурные формулы** (скелетные/бензольные кольца) — это уже не OCR, а химическая реконструкция (OSRA, DECIMER, MolScribe). Для текущего калькулятора, который работает с брутто-формулами и ионами, это не требуется на первом этапе.

## 3. Реалистичная точность

Оценки ниже — практические, не гарантия:

| Сценарий | Точность полной формулы/уравнения | Комментарий |
|---|---:|---|
| Чистый печатный текст, ровный свет | 85–95% | Лучший сценарий |
| Печатная формула со степенями/зарядами | 70–90% | Часты ошибки в индексах |
| Фото учебника под углом | 60–85% | Помогает crop/deskew/контраст |
| Рукописная печатная формула | 50–75% | Зависит от почерка |
| Рукописная прописная формула | 30–60% | Нельзя обещать автозамену |
| Сложная структурная формула | низкая без специализированной модели | Нужен отдельный стек |

Символьная точность обычного текста обычно 95–99%, но **химическая структура** (какой символ является индексом, а какой зарядом) — главный источник ошибок. Поэтому валидация через парсер и подтверждение пользователем обязательны.

## 4. Варианты стека

### Вариант A. Mathpix OCR (рекомендуемый MVP)

- API принимает изображение, возвращает LaTeX/текст.
- Сильная сторона — математика и формулы.
- Плюсы: быстрый старт, высокое качество, не нужна ML-инфраструктура.
- Минусы: платно, внешний сервис, задержка, зависимость от квот.
- Подходит для печатных формул и аккуратных фото.

### Вариант B. Google Cloud Vision / Yandex Vision / Azure AI Vision

- Хорошо читают печатный текст и документы.
- Формулы возвращают как текст, без гарантированной структуры.
- Плюсы: зрелые API, регионы, квоты.
- Минусы: нужна собственная химическая нормализация; хуже на формулах.

### Вариант C. Мультимодальная LLM (GPT-4o/Claude/Gemini/Qwen-VL)

- Может вернуть LaTeX/уравнение и объяснить.
- Плюсы: гибкость, обработка плохих фото, контекст.
- Минусы: галлюцинации, стоимость, задержка, приватность.
- Использовать только как fallback и **всегда** проверять парсером/балансировщиком.

### Вариант D. Self-hosted

- **Pix2Text / pix2tex / LaTeX-OCR** — формулы в LaTeX.
- **Tesseract** — только текст, формулы плохо.
- **PaddleOCR** — текст/документы.
- **MolScribe / DECIMER / OSRA** — структурные формулы.
- Плюсы: контроль данных, нет платы за каждый запрос.
- Минусы: GPU/CPU, DevOps, качество ниже Mathpix на сложных формулах.

### Вариант E. Полностью на устройстве

- `Tesseract.js` в браузере — 2–10 МБ WASM, приемлемо для текста, плохо для формул.
- ML Kit / Vision / Core ML — только в нативной обёртке, не в чистом Telegram WebView.
- Плюсы: приватность, офлайн.
- Минусы: качество и размер; для химии недостаточно.

## 5. Рекомендуемая архитектура для ChemCalc

```
Camera / file input
   ↓ (crop, rotate, contrast, JPEG)
POST /api/ocr  (image, source=calculator|stoichiometry)
   ↓
OCR provider: Mathpix primary
   ↓ fallback: Cloud Vision / multimodal LLM
Result: { text, latex, confidence, provider }
   ↓
normalizeChemInput()
   ↓
parseEquation / balanceEquation / inspectBalance
   ↓
Editable preview in UI
   ↓
Пользователь подтверждает → формула вставляется
```

Клиент:

- `<input type="file" accept="image/*" capture="environment">` — камера на телефоне.
- Canvas: crop, поворот, перспектива, повышение контраста, ограничение 1600–2000 px.
- Предпросмотр и кнопки «Переснять», «Вставить», «Исправить вручную».
- Не отправлять фото автоматически; только по кнопке.

Сервер:

- `POST /api/ocr` с лимитом 5–8 МБ, rate limit, проверка MIME.
- Провайдер выбирается через env; ключи только на сервере.
- Нормализация LaTeX → химическая запись: `\mathrm{}`, `\rightarrow`, `\to`, `_2`, `^{2-}`, `\cdot`.
- Валидация: `parseEquation` → `balanceEquation`; если не удалось, вернуть текст/LaTeX и подсветить проблему.
- Не хранить изображения дольше обработки без согласия; логировать только метаданные/ошибки.

## 6. Telegram Mini App

- Камера в WebView открывается через `<input type="file" accept="image/*" capture="environment">`.
- В Telegram iOS/Android это нативный выбор фото/камеры; отдельный SDK не нужен.
- Ограничения: размер фото, права камеры, WebView на iOS, медленная сеть.
- Отправлять сжатое изображение (обычно 300–800 КБ), не оригинал 12 МП.
- Показывать прогресс и возможность отмены.
- Для платного OCR — проверка entitlement до отправки, чтобы не тратить API-квоту.

## 7. Точность и UX

Рекомендуемая логика:

- **Высокая уверенность + парсер/баланс прошли** — предложить «Вставить», но оставить редактирование.
- **Средняя уверенность** — открыть редактируемое поле с подсветкой сомнительных символов.
- **Низкая уверенность** — показать распознанный текст и предложить ввести вручную; не блокировать калькулятор.
- Всегда показывать исходное изображение рядом с результатом.
- Для уравнений проверять не только синтаксис, но и баланс атомов/заряда; это мощный фильтр ошибок OCR.

## 8. Стоимость и производительность

- Mathpix/Cloud Vision/LLM — плата за изображение/токены; нужен лимит на пользователя.
- Латентность: 1–4 секунды у облака, 0.5–2 секунды у локальной модели на GPU.
- При 10 000 распознаваний/месяц расходы могут быть заметными; OCR логично сделать **Pro-функцией** или покупать пакетами.
- Кэширование по хэшу изображения снижает повторные расходы.
- Для массовых школ — self-hosted Pix2Text + очередь.

## 9. Оценка работ

| Этап | Срок |
|---|---|
| MVP: загрузка/камера, Mathpix, preview, вставка в калькулятор | 1–2 недели |
| Валидация формул, обработка ошибок, Telegram UX | 1–2 недели |
| Стехиометрия, история, лимиты/оплата | 1 неделя |
| Self-hosted fallback, мониторинг качества | 2–4 недели |
| Структурные формулы (MolScribe/DECIMER) | отдельный проект |

**Итог:** для текущего ChemCalc оптимален MVP на Mathpix (или Cloud Vision + LLM fallback) с обязательным редактируемым подтверждением. Полностью автоматическое распознавание с камеры без человека даст слишком высокий процент ошибок в химических зарядах и индексах.

## 10. Рекомендация

1. Сделать OCR отдельной кнопкой «С камеры» рядом с полем уравнения.
2. Начать с Mathpix + ручное подтверждение.
3. Добавить проверку `parseEquation`/`balanceEquation` и понятные ошибки.
4. Собрать статистику: доля успешных вставок, типы ошибок, стоимость одного распознавания.
5. Если OCR станет массовым — перейти на self-hosted Pix2Text и включить в Pro/школьную лицензию.
