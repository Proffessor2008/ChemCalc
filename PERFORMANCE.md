# Оптимизация производительности

Статус: первый проход выполнен в ветке `cam`.

## Что уже сделано

### 1. Ленивая загрузка OCR

Модуль `js/ocr-ui.js` больше не входит в стартовый граф `ui.js`.

- до первого нажатия камеры браузер не загружает и не разбирает OCR-интерфейс;
- модуль подгружается динамическим `import()` один раз;
- после загрузки открывается обычный диалог камеры;
- ошибка загрузки показывает уведомление, а не ломает калькулятор.

Размер `js/ocr-ui.js` — около 26 КБ. Это снимает его с критического пути первой отрисовки.

### 2. Общие DOM-хелперы

Создан `js/dom.js` с `element()` и `button()`.

Раньше одинаковые функции были продублированы в:

- `support-ui.js`;
- `review-ui.js`;
- `ocr-ui.js`;
- `donation-ui.js`.

Теперь они импортируются из одного модуля. Это уменьшает дублирование и риск расхождения поведения.

### 3. Кэширование статики

`server/static.mjs`:

- добавлены правильные MIME-типы для `.woff2`, `.woff`, `.ttf`;
- для CSS/JS/данных/шрифтов теперь `Cache-Control: public, max-age=300, must-revalidate`;
- HTML и manifest остаются `no-cache`;
- ETag и Brotli/Gzip сохранены.

Это уменьшает повторные сетевые запросы при переходах, не мешая обновлению HTML.

### 4. Ускорение первой загрузки Service Worker

Раньше активация Service Worker сразу запускала фоновую загрузку большого набора `FULL` (шрифты KaTeX, PDF/DOCX-модули, справочники и т. д.).

Теперь:

- оболочка `SHELL` кэшируется сразу;
- полный набор кэшируется с задержкой 2,5 секунды;
- OCR-модуль перенесён из `SHELL` в `FULL`, потому что он загружается только по нажатию камеры.

Это снижает конкуренцию за канал в первые секунды после открытия.

### 5. Modulepreload

В `index.html` добавлены `modulepreload` для критичных модулей:

- `i18n.js`;
- `parser.js`;
- `balancer.js`;
- `checker.js`;
- `auto-ui.js`.

Браузер начинает загружать их параллельно, а не после разбора `ui.js`.

### 6. Память и очистка

Проверены и сохранены:

- остановка камеры при закрытии OCR-диалога;
- освобождение `objectURL` для фото;
- отмена `requestAnimationFrame` в обучении;
- удаление таймеров поддержки при `pagehide`;
- отсутствие повторного создания обработчиков при ленивой загрузке OCR.

## Что ещё можно сделать

1. Разделить `i18n.js` (~91 КБ) на RU/EN и подгружать только нужный язык.
2. Лениво загружать `community-ui.js` (~70 КБ) при первом открытии сообщества или кабинета.
3. Разделить `styles.css` (~90 КБ) на критический CSS и стили второго экрана.
4. Лениво загружать `support-ui.js` и `review-ui.js` после первого простоя.
5. Разбить крупные JSON-справочники по разделам, чтобы не тянуть `elements.json` и `reaction-rules-final.json` целиком.
6. Добавить сборку/минификацию без изменения исходной структуры (например, esbuild только на деплое).
7. Провести замер Lighthouse на реальном URL после деплоя и зафиксировать LCP/INP/TBT.

## Что проверять после изменений

- камера по-прежнему открывается с первого нажатия;
- поддержка и отзыв открываются;
- офлайн-режим не сломан;
- после обновления Service Worker не остаются старые чанки;
- на медленном 3G первый экран появляется раньше, чем загружается OCR.
