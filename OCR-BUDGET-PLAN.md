# Бюджетное распознавание уравнений: Tesseract / PaddleOCR / OCR.space

Статус: **план, код не реализован.**  
Связанные документы: [OCR.md](./OCR.md), [OCR-PLAN.md](./OCR-PLAN.md).

## 1. Короткий вывод

Ни один из трёх вариантов не является «химическим OCR». Все они распознают **текст**, а не смысл уравнения. Поэтому надёжность даёт не сам OCR, а связка:

```text
crop → OCR → нормализация → parseEquation/balanceEquation → подтверждение пользователем
```

Рекомендация по бюджету:

1. **MVP: OCR.space Free API** — самый быстрый и дешёвый способ проверить спрос.
2. **При росте объёма: self-hosted PaddleOCR** на недорогом VPS — нет платы за каждый запрос.
3. **Tesseract** — только офлайн/аварийный fallback, не основной движок.
4. Если после замеров точности результат недостаточен — закладывать Mathpix/pix2tex как платный/тяжёлый fallback. Generic OCR не исправит химические заряды и индексы сам.

## 2. Сравнение

| Критерий | Tesseract | PaddleOCR | OCR.space Free |
|---|---|---|---|
| Стоимость | 0 | 0 + VPS | 0 |
| Где работает | локально/сервер | свой Python/Docker | облако |
| Печатный текст | средне | хорошо | хорошо |
| Формулы, индексы, заряды | плохо | средне | средне |
| Рукописный текст | плохо | ограниченно | Engine 3 лучше |
| Русский/английский | да | да | да |
| Задержка | зависит от CPU | 1–5 с на CPU | 1–4 с |
| Лимиты | нет | нет, только железо | 25 000/мес, 500/день/IP, 1 МБ |
| Приватность | данные не уходят | данные не уходят | изображение уходит в OCR.space |
| Сложность внедрения | средняя | высокая | низкая |
| Надёжность для химии | низкая | средняя | средняя |

### OCR.space

По официальной документации бесплатный тариф:

- **25 000 запросов в месяц**;
- **500 запросов в день на IP**;
- **1 МБ на файл**;
- 3 страницы PDF;
- Engine 2 — обычный печатный текст;
- Engine 3 — handwriting/таблицы, **1 000 бесплатных запросов в месяц** дополнительно;
- SLA на free-тарифе нет.

Источник: [OCR.space API docs](https://ocr.space/ocrapi).

Плюсы:

- не нужно поднимать ML;
- ключ и запросы через сервер;
- 1 МБ хватает для crop;
- бесплатно для MVP.

Минусы:

- бесплатный сервис без SLA;
- 500/день на IP — при общем IP Render это ограничение на всё приложение;
- изображение уходит стороннему сервису;
- формулы и заряды всё равно нужно нормализовать и проверять.

### PaddleOCR

PP-OCRv5 — сильный open-source OCR для текста; у PaddleOCR есть отдельный **Formula Recognition** модуль для формул.

Источники:

- [PP-OCRv5](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5.html)
- [Formula Recognition Module](https://www.paddleocr.ai/latest/en/version3.x/module_usage/formula_recognition.html)

Плюсы:

- бесплатно при своём железе;
- данные не уходят наружу;
- можно обрабатывать большие объёмы;
- есть formula recognition.

Минусы:

- нужен Python/PaddlePaddle и отдельный сервис;
- на Render бесплатного Node-инстанса это не поднять;
- CPU-инференс медленнее;
- обновление моделей/зависимостей — ваша ответственность;
- для химических уравнений всё равно нужна нормализация.

Ориентир по серверу: 2 vCPU / 4 ГБ RAM, 10–20 ГБ диска; GPU не обязателен, но ускорит. Дешёвый VPS обычно $5–20/мес.

### Tesseract

- бесплатный, локальный;
- хорошо читает обычный текст;
- **плохо** сохраняет индексы, степени, заряды и стрелки;
- не понимает химическую структуру;
- подходит как офлайн-fallback, но не как основной движок.

## 3. Рекомендуемая схема на бюджете

### Этап 1 — OCR.space Free API

```text
Клиент: crop 1600 px, JPEG ≤ 900 КБ
   ↓
Node /api/ocr (ключ только на сервере)
   ↓
OCR.space Engine 2
   ↓ (если текст не похож на уравнение и Engine 3 доступен)
OCR.space Engine 3
   ↓
normalizeOcrEquation()
   ↓
parseEquation + balanceEquation
   ↓
пользователь подтверждает вставку
```

Почему Engine 2, а не сразу Engine 3:

- Engine 3 имеет лимит 1 000/мес;
- Engine 2 дешевле по квоте и быстрее;
- Engine 3 включать только для handwriting или если Engine 2 не дал уравнение.

### Этап 2 — PaddleOCR

Когда упрётесь в лимиты/качество:

- отдельный Docker-сервис `paddle-ocr`;
- Node проксирует запросы туда;
- OCR.space остаётся fallback;
- можно использовать text OCR + formula module;
- данные не покидают ваш сервер.

### Этап 3 — платный fallback

Если качество ниже приемлемого:

- Mathpix (лучшее качество для формул, платно);
- или pix2tex/Pix2Text как self-hosted формульный OCR;
- OCR.space/Paddle остаются для дешёвого текста.

## 4. Что именно должен сделать ты

### Обязательно для OCR.space MVP

1. **Зарегистрировать бесплатный ключ OCR.space** на [ocr.space/ocrapi/freekey](https://ocr.space/ocrapi/freekey).
2. **Не присылать ключ в чат и не коммитить в репозиторий.** Добавить его в Render → Environment:
   - `OCR_PROVIDER=ocrspace`
   - `OCR_SPACE_API_KEY=...`
   - `OCR_DAILY_LIMIT=...`
3. **Принять условия OCR.space и их политику приватности**; проверить, что отправка фото уравнения вас устраивает.
4. **Дать 15–30 тестовых фото**:
   - печатные уравнения;
   - фото под углом;
   - плохой свет;
   - степени/заряды;
   - 5–10 рукописных.
   К каждому — ожидаемое уравнение. Без этого нельзя честно выбрать движок.
5. **Решить доступ:**
   - OCR только для авторизованных;
   - только авторизованные: 5 сканов в день; анонимным показывается приглашение зарегистрироваться.
6. **Подтвердить лимит расходов**: на free-тарифе $0; если понадобится PRO — $30/мес по текущей странице OCR.space.
7. **Подтвердить, что фото не сохраняются** (рекомендуемый вариант) и что политика конфиденциальности будет обновлена.
8. **Проверить Telegram**: камера через `input capture` и/или `getUserMedia`.

### Если выбираем PaddleOCR

1. Дать **VPS или отдельный Render-сервис**:
   - 2 vCPU;
   - 4 ГБ RAM;
   - Docker;
   - желательно 10–20 ГБ диска.
2. Разрешить отдельный Python/Docker-сервис в деплое.
3. Дать доступ/способ деплоя (SSH, Docker registry, Render service).
4. Согласовать, что модели PaddleOCR будут скачиваться на сервере.
5. Дать те же тестовые фото для сравнения с OCR.space.

### Если выбираем Tesseract

1. Подтвердить, что готовы к меньшей точности.
2. Дать сервер/ПК для `tesseract` и языковых пакетов (`rus`, `eng`).
3. Согласовать, что Tesseract — только fallback/офлайн, не основной.

## 6. Бюджет

| Статья | Ориентир |
|---|---|
| OCR.space Free | $0 |
| OCR.space PRO, если понадобится | $30/мес по текущей странице |
| PaddleOCR VPS | ~$5–20/мес |
| PaddleOCR разработка/DevOps | основная стоимость — время |
| Tesseract | $0 + время |
| Mathpix fallback | по тарифу провайдера, требует отдельного решения |

Самый дешёвый старт — **$0**: OCR.space Free + crop + ручное подтверждение.

## 7. План проверки до кода

1. Взять 20–30 фото.
2. Прогнать через OCR.space вручную/скриптом:
   - Engine 2;
   - Engine 3;
   - `scale=true`;
   - `detectOrientation=true`.
3. Замерить:
   - распознан ли текст;
   - совпало ли уравнение полностью;
   - сколько символов ошибок;
   - проходит ли `parseEquation`;
   - проходит ли баланс;
   - сколько времени;
   - сколько запросов/стоимость.
4. Порог для MVP:
   - ≥80% печатных фото дают пригодный результат после ручной правки;
   - ≥90% не падают с ошибкой сервиса;
   - среднее время <5 с;
   - payload <1 МБ.
5. Если хуже — не тратить недели на камеру, а сразу решать вопрос платного fallback.

## 8. Риски

| Риск | Что делать |
|---|---|
| OCR.space free нестабилен | таймаут, fallback, ручной ввод |
| 500/день на IP | лимит на пользователя, очередь, Paddle |
| 1 МБ | crop ≤900 КБ |
| Химические заряды/индексы | нормализация + парсер + подтверждение |
| Приватность | не хранить фото, предупредить, политика |
| Telegram не даёт камеру | file input + crop fallback |
| Paddle требует RAM | VPS 4 ГБ, отдельный сервис |
| Tesseract ошибается | не делать основным |

## 9. Итоговая рекомендация

**Начать с OCR.space Free API + crop + подтверждение.** Это самый бюджетный и быстрый способ получить работающую функцию и собрать статистику.

Через 2–4 недели использования:

- если лимиты/точность устраивают — оставить;
- если много запросов — перенести на PaddleOCR VPS;
- если качество химии недостаточно — добавить Mathpix/pix2tex как платный fallback.

Tesseract не делать основным: он дешёвый, но для химических уравнений слишком часто теряет индексы и заряды.
