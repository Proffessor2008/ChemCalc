# ChemCalc: аудит производительности, утечек памяти и монетизация

Документ фиксирует результаты технического аудита, внесённые исправления, проверку и коммерческие сценарии.

## 1. Методика аудита

Проверены:

- все клиентские ES-модули (`js/*.js`) и стили;
- серверные модули (`server/*.mjs`, `server.mjs`);
- жизненный цикл сессии, SSE, таймеров и подписок;
- повторяющиеся рендеры таблиц, PDF/DOCX, Q&A и сообщества;
- рост in-memory структур на сервере;
- размеры данных, service worker и кэш;
- тесты (61 файл) и браузерные сценарии.

Поиск вёлся по `addEventListener`, `setInterval`, `setTimeout`, `Map`, `Set`, `EventSource`, `createObjectURL`, `requestAnimationFrame`, `innerHTML`, `JSON.parse`, серверным `EventEmitter` и таблицам БД.

## 2. Найденные проблемы и исправления

### 2.1. Клиент

| Проблема | Риск | Исправление |
|---|---|---|
| Форма входа мелькала при перезагрузке, пока `/api/auth/me` не вернёт сессию | UX/лишние действия | Состояние `restoring`, снимок профиля, скрытая форма до окончательного 401 |
| `EventSource` и 30-секундный `setInterval` не закрывались при уходе со страницы | утечка соединения/таймера при bfcache/повторной инициализации | `pagehide` очищает интервал, SSE и таймер обновлений |
| RAF в онбординге мог подсветить элемент после закрытия тура | «залипший» `tour-target`, лишний DOM-класс | `cancelAnimationFrame`, проверка `isConnected`, удаление старого тура при рестарте |
| Карты черновиков комментариев/ответов и открытых редакторов росли без ограничения | медленный рост памяти в долгой сессии | лимит 100 записей на карту |
| Canvas/Image в PDF не освобождались сразу | высокий пик памяти на мобильных | сброс `canvas.width/height`, очистка `image.src` после кадра |
| Таймеры Telegram SDK/download и Clipboard API не очищались | висящие таймеры | `clearTimeout` в `finish/finally` |
| Аватары в Q&A декодировались все сразу | лишняя работа на длинных списках | `loading="lazy" decoding="async"` |
| В сигнатуре авторизации сравнивался весь data-URL аватара | лишние строковые операции | сравнение по длине и хвосту |
| Снимок профиля перезаписывался каждые 30 секунд | синхронная запись в localStorage | запись только при изменении пользователя |
| Удалённые разделы документации оставили мёртвый CSS и i18n-ключи | мусор в бандле | удалены `.docs-*`, `.documentation-*`, `documentation/docsSubtitle/openReadme` |

### 2.2. Сервер

| Проблема | Риск | Исправление |
|---|---|---|
| `attempts` Map рос по уникальным IP | утечка памяти при большом трафике | периодическая очистка раз в 5 минут |
| `EventEmitter` для SSE имел лимит 10 слушателей | предупреждения/проблемы при >10 клиентах | `setMaxListeners(0)` |
| SSE-клиент очищался только по `request.close` | «мёртвые» response при ошибке | идемпотентная очистка по `request.close`, `response.close`, `response.error` |
| Просроченные сессии накапливались | рост таблицы | удаление истёкших при создании сессии + индекс `sessions_expires` |
| Уведомления копились без ограничения | рост БД | хранение последних 200 на пользователя |
| Временные файлы PDF/DOCX могли занять много памяти | OOM | лимит 6 МБ на файл, 20 файлов/40 МБ, TTL 10 минут |
| Rate limit использовался и для загрузки файлов | возможное влияние на логин | ограничение по IP сохранено, добавлена очистка |

### 2.3. Производительность и данные

- Тяжёлые справочники, таблица Менделеева, стехиометрия, термодинамика и экспорт по-прежнему загружаются лениво.
- PDF растворимости укладывается в 2 страницы: по 23 аниона на страницу, заголовки формул вертикальные без переносов, все данные сохраняются.
- Статический сервер кэширует до 64 файлов и отдаёт Brotli/Gzip; кэш ограничен.
- Service worker не кэширует API и приватные ответы.
- Для PDF освобождаются canvas/Image; для скачивания — object URL.

### 2.4. Что осталось в бэклоге

1. Аватары хранятся как data URL и попадают в JSON автора; для больших сообществ лучше отдельный `/api/avatars/:id` с кэшем.
2. Q&A-детализация делает отдельные запросы комментариев/правок на каждый ответ (N+1). При росте количества ответов стоит агрегировать одним запросом.
3. PDF собирается в браузере через canvas; на слабых телефонах широкие таблицы остаются заметной нагрузкой. Можно снизить scale для широких таблиц или генерировать PDF на сервере.
4. Нет CSP; при добавлении внешних источников/платежей стоит ввести явную политику.
5. Часть HTML собирается через `innerHTML` с экранированием; лучше постепенно переводить на DOM API.
6. Нет автоматического бюджета памяти/размера ответа в CI; можно добавить лимиты на JSON API и PDF.

## 3. Проверка

- 66 тестовых файла проходят.
- `validate-data` — 0 ошибок, 0 предупреждений.
- Браузерные проверки:
  - перезагрузка с активной сессией: форма входа не показывается, статус «Восстанавливаем сессию…», затем профиль;
  - искусственная задержка `/api/auth/me` 2,5 с — поведение корректное;
  - cookie сессии ~30 дней;
  - PDF растворимости — 2 страницы, вертикальные заголовки без переносов, данные полные;
  - мобильные ширины 320/360/390 — без горизонтального переполнения.

## 4. Монетизация: сценарии

### 4.1. Что уже является ценностью

- точный балансировщик и проверка реакций;
- справочники, растворимость, термодинамика, электрохимия;
- расчёты по стехиометрии и отчёты PDF/DOCX;
- офлайн/PWA и Telegram Mini App;
- сообщество с проверенными заявками и Q&A.

Ядро (калькулятор и базовая проверка) лучше оставить бесплатным: это источник трафика, репутации и SEO.

### 4.2. Сценарии

| Сценарий | Кому | Плюсы | Минусы | Потенциал |
|---|---|---|---|---|
| **Freemium Pro** | студенты, школьники, преподаватели | понятная ценность: экспорт без ограничений, расширенные отчёты, синхронизация, история, приоритетные функции | низкая конверсия, чувствительность к цене | высокий |
| **B2B-лицензии школам/вузам** | школы, колледжи, вузы, репетиторы | высокий чек, bulk-лицензии, методические материалы | долгие продажи, поддержка, закупки | очень высокий |
| **Telegram Stars: разовые покупки** | пользователи Mini App | низкий порог, встроенная оплата, импульсные покупки | комиссия Telegram, ограничения цифровых товаров | средний |
| **Платный API/SDK** | разработчики, EdTech, сайты | масштабируется, не требует UI | нужны ключи, лимиты, поддержка, SLA | средний/поздний |
| **Партнёрства с репетиторами/курсами** | EdTech | лиды, реферальные выплаты | зависимость от партнёров | средний |
| **Реклама/спонсорство** | химические поставщики, лаборатории | простота | ухудшает UX, риск для образовательного бренда | низкий |
| **Платные экспертные ответы** | студенты | высокая ценность | модерация, доверие, юридические риски | низкий/средний |

### 4.3. Наиболее перспективная стратегия

**Основная:** Freemium-подписка Pro для студентов и преподавателей + отдельная B2B-лицензия для школ.

Почему:

- ядро остаётся бесплатным, поэтому не падает трафик и сообщество;
- платить готовы за экономию времени: отчёты, расширенные расчёты, синхронизация, готовые методички;
- школа/вуз платит за класс, а не за одного ученика — выше LTV;
- Telegram Mini App даёт дешёвый канал привлечения и оплату Stars;
- API можно продавать позже, когда появится стабильная база и документация.

**Рекомендуемая последовательность:**

1. **0–3 месяца:** бесплатный Pro-триал, платный пакет PDF/DOCX и Pro-подписка через Telegram Stars и Stripe. Замерить долю экспортов, retention, willingness to pay.
2. **3–6 месяцев:** годовая student-Pro со скидкой; teacher-план с шаблонами отчётов; первые 5–10 школ по пилотной цене.
3. **6–12 месяцев:** школьные лицензии, LMS/white-label, API с лимитами.

### 4.4. Ориентировочная экономика

Пример (не прогноз):

- 10 000 MAU, конверсия в Pro 3%, цена 199 ₽/мес → ~60 000 ₽/мес gross;
- 20 школ × 40 000 ₽/год → ~800 000 ₽/год;
- комиссия Telegram/платежей, налоги и поддержка снижают маржу;
- B2B даёт меньший объём клиентов, но значительно больший чек.

Ключевые метрики: conversion to paid, trial→paid, monthly churn, ARPPU, доля экспортов, retention 7/30 дней, стоимость поддержки.

### 4.5. Технические требования к монетизации

- таблицы `plans`, `subscriptions`, `orders`, `entitlements`;
- идемпотентные webhook-и Stripe/Telegram;
- Telegram Stars: `createInvoiceLink` с валютой `XTR`, обработка `pre_checkout_query` и `successful_payment`;
- восстановление покупок и привязка к аккаунту;
- feature flags/лимиты: экспорт, история, расширенные отчёты;
- аналитика событий: `export_started`, `export_completed`, `paywall_shown`, `checkout_started`, `purchase_completed`;
- чеки, возвраты, налоги, политика конфиденциальности, согласие родителей для несовершеннолетних;
- не блокировать доступ к уже созданным пользовательским данным при отмене подписки;
- не продавать персональные данные и не ставить рекламу в образовательных разделах для детей.

### 4.6. Риски монетизации

- низкая платёжеспособность части аудитории;
- сезонность (учебный год);
- комиссии и правила Telegram/App Store для цифровых товаров;
- поддержка школ требует SLA и документов;
- ограничения лицензий на справочные данные;
- репутационный риск от навязчивой рекламы.

## 5. Итоговая рекомендация

Начинать не с рекламы и не с закрытия калькулятора, а с **Pro-подписки на отчёты/расширенные функции** и **пилотов со школами**. Это сохраняет бесплатное ядро, использует уже готовые PDF/DOCX и Telegram-канал, а B2B-лицензии дают лучший чек. API и white-label — следующий этап после подтверждения спроса.
