# План внедрения распознавания уравнений по камере/фото

Статус: **проектирование, код ещё не реализован.**  
Связанный анализ точности и провайдеров: [OCR.md](./OCR.md).

## 1. Что делаем

В правом конце полей ввода уравнений появляется кнопка камеры. Нажатие открывает сценарий:

1. Снять фото камерой или выбрать изображение.
2. Показать рамку-видоискатель.
3. Вырезать **только область внутри рамки** на canvas.
4. Отправить уменьшенный фрагмент на OCR.
5. Показать распознанное уравнение, уверенность и кнопки «Вставить», «Исправить», «Переснять».
6. Вставить в поле только после подтверждения пользователя.

Кнопка добавляется в:

- `#equation-input` — проверка полного уравнения;
- `#auto-input` — подбор реагентов (из OCR берётся левая часть уравнения);
- `#stoich-equation` — стехиометрия.

Для всех трёх полей используется один компонент, чтобы не дублировать логику.

## 2. Ключевое решение по камере

### 2.1. Два режима, один результат

**Режим A — встроенная камера (рекомендуется как основной там, где работает):**

- `navigator.mediaDevices.getUserMedia({ video: { facingMode: { ideal: 'environment' } } })`;
- полноэкранный `<video>` с затемнением вокруг рамки;
- рамка 16:9 или 3:2, подсказка «Поместите уравнение в рамку»;
- кнопка съёмки, переключение камеры, отмена;
- при съёмке рисуем в canvas **только область рамки**, а не весь кадр.

**Режим B — системная камера / выбор файла (fallback):**

- `<input type="file" accept="image/*" capture="environment">`;
- после выбора фото открывается **crop-редактор** с той же рамкой;
- пользователь двигает/масштабирует фото под рамкой, при необходимости поворачивает;
- в OCR уходит только вырезанный прямоугольник.

Почему fallback обязателен:

- Telegram WebView и iOS могут ограничивать `getUserMedia`;
- нет разрешения на камеру;
- пользователь хочет загрузить уже готовое фото;
- в некоторых браузерах камера доступна только через системный picker.

### 2.2. Как режется кадр

Для live-камеры:

- получаем реальные `videoWidth × videoHeight`;
- учитываем `object-fit: cover` и масштаб отображения;
- координаты рамки в CSS-пикселях переводим в пиксели видео;
- `drawImage(video, sx, sy, sw, sh, 0, 0, outW, outH)`;
- ограничиваем长 сторону 1600 px;
- `canvas.toBlob(..., 'image/jpeg', 0.82)`.

Для фото:

- фото показывается под фиксированной рамкой;
- пользователь pan/zoom;
- из текущего transform вычисляется исходный прямоугольник;
- тот же `drawImage` и ограничение размера.

### 2.3. Почему это важно

- Меньше пикселей → быстрее загрузка, OCR и ответ.
- Меньше лишнего текста → меньше ложных срабатываний.
- Ниже стоимость запроса к платному OCR.
- Меньше риск отправить на сторонний сервис лишние данные (лица, документы, фон).

Ориентир: 200–700 КБ на кадр вместо 3–8 МБ; отправляется только область уравнения.

## 3. OCR-провайдер

### Рекомендация для MVP

**Mathpix OCR как основной провайдер.**

Почему:

- лучший практический результат для формул и LaTeX;
- понимает степени, индексы, заряды, стрелки;
- есть confidence/структурированный ответ;
- не нужно поднимать ML-инфраструктуру.

Fallback:

- Google Cloud Vision / Yandex Vision — если Mathpix недоступен или для простого печатного текста;
- мультимодальная LLM — только как эксперимент, не как единственный источник;
- **Pix2Text/pix2tex** — позже, при больших объёмах и необходимости self-hosted.

Не использовать Tesseract как основной OCR для химии: он хорошо читает текст, но плохо сохраняет индексы и заряды.

### Серверный интерфейс

Новый модуль `server/ocr.mjs`:

```text
recognizeImage({ buffer, mime, context })
  → { text, latex, confidence, provider, warnings }
```

Новый endpoint:

```text
POST /api/ocr
```

Тело: `{ image: base64, mime: 'image/jpeg', context: 'calculator'|'auto'|'stoichiometry' }`.

Ограничения:

- только JPEG/PNG/WebP;
- максимум 2 МБ после crop;
- проверка сигнатуры файла;
- таймаут провайдера 8–12 секунд;
- ошибки провайдера не раскрывают ключи и внутренние детали;
- ключи только в env: `MATHPIX_APP_ID`, `MATHPIX_APP_KEY`, `OCR_PROVIDER`.

### Квоты

Рекомендуемая схема:

- анонимно: 2–3 распознавания в сутки на visitor-cookie/IP;
- авторизованный: 20 в сутки;
- Pro/школа: пакет или повышенный лимит;
- отдельный rate limit и журнал количества, без хранения изображений.

Альтернатива для первого релиза: OCR только для авторизованных. Это проще по стоимости, но ухудшает первый опыт анонимного калькулятора. Рекомендую небольшой анонимный лимит.

## 4. Нормализация результата

OCR вернёт смесь текста и LaTeX. Нужен слой `normalizeOcrEquation`:

- убрать `\mathrm{}`, `\ce{}`, `\left`, `\right`;
- Unicode-индексы `₃` → `3`, степени `²⁺` → `^2+`;
- стрелки `⟶`, `→`, `=>` → `=`;
- убрать пробелы внутри формул, сохранить пробелы вокруг `+` и `=`;
- склеить переносы строк;
- убрать состояния `(aq)`, `(s)`, `(l)`, `(g)`, если поле их не поддерживает;
- сохранить исходный OCR-текст для показа пользователю.

Пример:

```text
C₃H₈ + 5O₂ → 3CO₂ + 4H₂O
→ C3H8 + 5O2 = 3CO2 + 4H2O
```

После нормализации:

1. `parseEquation` — синтаксис;
2. `balanceEquation` — баланс;
3. если не удалось — показать исходный вариант и подсветить проблему;
4. никогда не вставлять автоматически без подтверждения.

Для `#auto-input` берём левую часть до `=`/стрелки. Если уравнение уже полное, предложить выбор «Вставить реагенты» или «Открыть в проверке уравнения».

## 5. UI/UX

### Кнопка в поле

- Камера-иконка справа внутри поля.
- Поле получает `padding-right: 44px`, чтобы текст не заходил под кнопку.
- Кнопка `type="button"`, `aria-label="Распознать уравнение по фото"`.
- На мобильном — 40×40 px, не перекрывает ввод и очистку.
- При наличии значения кнопка не стирает его: сначала предпросмотр, потом замена.

### Сценарий

**Шаг 1. Выбор источника**

- «Снять на камеру»;
- «Загрузить фото»;
- отмена.

**Шаг 2. Видоискатель**

- live-камера с рамкой или фото под рамкой;
- подсказка: «Держите уравнение ровно, без бликов»;
- кнопки «Снять», «Повернуть», «Отмена»;
- на мобильном учитывать safe-area и кнопку «Назад» Telegram.

**Шаг 3. Проверка crop**

- миниатюра вырезанной области;
- кнопки «Переснять», «Распознать».

**Шаг 4. Результат**

- изображение crop рядом с распознанным текстом;
- уверенность: высокая / средняя / низкая;
- редактируемое поле с LaTeX/уравнением;
- «Вставить в поле», «Исправить», «Переснять».

**Шаг 5. Вставка**

- заполнить поле;
- вызвать `input`/`change`;
- сфокусировать поле;
- не запускать расчёт автоматически;
- для `auto` показать, что взята левая часть.

### Ошибки

- нет камеры/разрешения;
- пустой crop;
- OCR не нашёл уравнение;
- сервис недоступен;
- превышена квота;
- слишком большой файл;
- не удалось проверить баланс.

Каждая ошибка — понятный текст и действие «Попробовать снова» / «Ввести вручную».

## 6. Архитектура

### Клиент

- `js/ocr-camera.js` — getUserMedia, video, frame, canvas crop, fallback file input;
- `js/ocr-ui.js` — диалог, шаги, preview, вставка в поля;
- общий компонент камеры для трёх input-полей.

### Сервер

- `server/ocr.mjs` — провайдер, нормализация ответа, таймауты;
- маршрут в `server/app.mjs`;
- лимиты, auth/cookie, origin, rate limit;
- без записи изображений по умолчанию.

### Конфигурация

```text
OCR_PROVIDER=mathpix
MATHPIX_APP_ID=...
MATHPIX_APP_KEY=...
OCR_DAILY_ANONYMOUS=3
OCR_DAILY_USER=20
```

## 7. Приватность и безопасность

- Изображение уходит стороннему OCR-провайдеру; это нужно явно указать в интерфейсе.
- Отправлять только crop, не весь экран.
- Не хранить изображения по умолчанию; только временно в памяти.
- Не логировать содержимое изображений и распознанный текст.
- Ключи только на сервере.
- Лимиты и защита от спама.
- Проверка MIME по сигнатуре.
- HTTPS.
- Политика конфиденциальности: новый подпроцессор/передача данных.
- Не отправлять фото документов, лиц и других чувствительных данных; подсказка в UI.

## 8. Тестирование

### Unit

- геометрия crop для `object-fit: cover`;
- поворот/pan/zoom;
- нормализация Unicode/LaTeX;
- разбиение уравнения на реагенты для `auto`;
- fallback при отсутствии `getUserMedia`.

### API

- неверный MIME/размер;
- отсутствие auth/квоты;
- таймаут провайдера;
- mock Mathpix success/error;
- отсутствие утечки ключей.

### Browser

- загрузка файла → crop → распознавание (mock provider);
- вставка в три поля;
- отмена/повтор;
- мобильная ширина 320/360/390;
- Telegram WebView (ручная проверка).

### Качество

Собрать 30–50 реальных фото:

- печатное уравнение;
- фото под углом;
- плохой свет;
- степени/заряды;
- рукописный вариант;
- несколько уравнений в кадре.

Метрики:

- точное совпадение всего уравнения;
- ошибка по символам;
- доля успешного баланса после вставки;
- доля исправлений пользователем;
- среднее время ответа;
- стоимость одного распознавания.

Ориентир приёмки:

- чистый печатный текст: ≥85% пригодных вставок;
- фото под углом: ≥70%;
- handwriting: не обещать высокую точность, только с ручной правкой.

## 10. Риски

| Риск | Мера |
|---|---|
| Ошибки в зарядах/индексах | обязательный preview, парсер и балансировщик |
| Дорогие запросы | квоты, crop, кэш по хешу, Pro-пакеты |
| Анонимный спам | cookie/IP-лимит, авторизация для больших квот |
| Telegram не даёт камеру | file input + crop fallback |
| Провайдер недоступен | таймаут, fallback, сообщение пользователю |
| Приватность | не хранить фото, отправлять только crop, обновить политику |
| Сложность UI | один компонент, 4 шага, понятные ошибки |
| Ложная уверенность | не вставлять без подтверждения |

## 11. Что предлагаю решить до кода

1. **Провайдер:** Mathpix как основной? Есть ли бюджет/ключи?
2. **Доступ:** OCR только авторизованным или 2–3 бесплатных анонимных скана?
3. **Поля:** сразу все три (`equation`, `auto`, `stoich`) или сначала `equation`?
4. **Live-камера:** нужна ли встроенная камера или достаточно системной камеры + crop?
5. **Хранение:** сохранять ли crop для отладки (по умолчанию — нет)?
6. **Рукописные уравнения:** входят в MVP или только печатные?
7. **Автозапуск:** после вставки сразу считать или оставить пользователю кнопку?

## 12. Рекомендуемый первый релиз

1. Кнопка камеры в поле полного уравнения.
2. Системная камера/файл + **crop-редактор с рамкой**.
3. Mathpix на сервере.
4. Нормализация и проверка через парсер/балансировщик.
5. Preview с уверенностью и кнопкой «Вставить».
6. 3 анонимных скана/сутки, 20 для аккаунта.
7. Затем — auto/stoich и live-камера с overlay.

Такой вариант даёт пользователю обещанную «рамку» уже в MVP, не завися от поддержки `getUserMedia` в Telegram, и при этом отправляет на OCR только вырезанную область.
